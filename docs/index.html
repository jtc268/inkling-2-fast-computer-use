8.95× faster on WebArena 190

Inkling 2 Mini took 45.89 seconds to find the latest completed order total. After a four-row weight edit, it returned the same answer ($65.32) in 5.13 seconds on an M5 Max MacBook Pro.

What changed in the model

For the completed-order checkpoint, we edited four rows of model.llm.unembed.weight, the matrix that maps the model’s hidden state to next-token scores. We exchanged the answer-text and thinking rows (200004 and 200008) and adjusted the click-command and end-of-generation rows (34 and 200006). A byte comparison found 9,192 changed BF16 values. We used no additional training.

The original and edited models issued the same three clicks. The original also generated one empty action. Most of the elapsed-time difference came from generating fewer tokens before responding.

Inference setup

Both models read visible text and numbered controls from Brave, used greedy decoding with reasoning_effort=none, and had identical cursor timing. On WebArena we reset the fixture between arms. Task 190 was a development task. The film shows the faster of two passing pairs. The pair with reversed run order measured 8.00×.

On the 128 GiB Mac, both checkpoints peaked at 20.8 GiB of active MLX memory during a replay of the filmed order lookup. This measures model inference. Memory measurements

Reproduce WebArena 190

Install Brave, Docker and uv on Apple silicon. Start Docker with Linux/AMD64 emulation enabled. The runner downloads both pinned checkpoints, verifies their weight hashes and runs the two model orders against fresh store fixtures.

git clone https://github.com/jtc268/inkling-2-fast-computer-use.git
cd inkling-2-fast-computer-use
uv sync --locked --python 3.12 --extra webarena
.venv/bin/playwright install ffmpeg
.venv/bin/python benchmark/reproduce_browser.py --out runs/mac-headline

Read runs/mac-headline/pairs.json for scores and times in both orders. Setup and grade replay
